# Bundled fallback batches

Insurance for the demo (ARCH §5 and §7). Any pipeline stage erroring — or the
whole run passing 90s — drops the app here instead of showing the child a
spinner that never ends.

- `batch.json` — the rehearsal batch, on-level.
- `challenge-batch.json` — the pre-cached Challenge batch that **Make it harder**
  serves on the demo path (ARCH §5).

Both ship **without** `imageUrl` / `audioUrl`: fal and ElevenLabs URLs expire, so
the media is saved as *files* and re-attached by key at runtime. The specs also
play fine with no media at all — the player renders each caption over a tinted
gradient and auto-advances on a read-length timer instead of on clip end.

## The media files

`<variant>-g<groupIndex>-s<slideIndex>.{jpg,mp3}`, where the variant is `b` for
the on-level batch and `c` for the Challenge one. Both batches are read through
the single `bundledMedia` map in [`../../lib/fallback.ts`](../../lib/fallback.ts),
so the variant is what keeps them apart — without it the Challenge batch would
play the on-level batch's illustrations and narration on the Make-it-harder beat.

Metro resolves `require()` at build time from a literal path, so every asset has
to be listed in that map by hand. It is generated, between the
`--- generated by scripts/bundle-fallbacks.ts ---` markers; edit the generator,
not the region.

## Before the demo: refresh the media

Run the pipeline cleanly at both levels, then bundle each result. The API server
must still be running when you bundle — with no `BLOB_READ_WRITE_TOKEN` the audio
is served from an in-process store that dies with the server.

```sh
cd api
npm run dev                                          # leave running

npm run smoke -- ./fixtures/worksheet.jpg on-level
npm run bundle:fallbacks -- ./batch-on-level.json

npm run smoke -- ./fixtures/worksheet.jpg challenge
npm run bundle:fallbacks -- ./batch-challenge.json

npm run validate:fallbacks                           # expect 8/8 on both
```

`bundle:fallbacks` does all four steps the old checklist did by hand: validates
the batch against the real `BatchSpec`, downloads every image and clip (decoding
`data:` URIs inline if that is how audio came back), writes the spec back with
the dead URLs stripped, and regenerates `bundledMedia` from what is on disk. It
rewrites nothing if any download fails, so a half-bundled batch cannot reach the
demo.

Re-bundling one level never deregisters the other — the map is rebuilt by
scanning the folder, not from the run in hand.
